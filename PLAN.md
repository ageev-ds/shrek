# PLAN.md — «Своя игра: Шрек»

Настольная викторина в формате «Своей игры» по вселенной Шрека, подарок ко дню рождения.
Windows `.exe` (portable + NSIS-установщик), Electron + React 18 + TypeScript + Vite.

> Статус: **черновик плана, до начала кодинга**. По мере реализации раздел «Фактическая реализация» в конце будет обновляться.

---

## 0. Где живёт проект

Целевой репозиторий — `ageev-ds/shrek` (создаётся пользователем вручную, т.к. у GitHub-интеграции нет права создавать репозитории).

## 1. Стек и зависимости

| Слой | Выбор | Зачем |

## 3. Модель данных (`src/types/game.ts`)

```ts
interface GameData {
  schemaVersion: 1;
  meta: { title: string; subtitle: string };           // «СВОЯ ИГРА: ШРЕК», «С днём рождения!»
  settings: {
    defaultTimerSec: number;        // 30
    catInBagTimerSec: number;       // 45
    auctionTimerSec: number;        // 40
    soundEnabled: boolean; volume: number;             // 0..1
    devPassword: string;            // '' = без пароля
    wrongAnswerPenalty: boolean;    // снимать очки за неверный ответ (классика: да)
  };
  levels: { id: string; value: number }[];            // 100..500, редактируется
  categories: Category[];
  backgrounds: {
    library: Background[];          // встроенные (builtin: true) + загруженные
    active: { menu: string; board: string; question: string; finale: string }; // id фона
    blur: number; dim: number;      // 0..20 px, 0..0.9
  };
  defaultTeams: { name: string; avatar: AvatarId }[];
}
interface Category {
  id: string; title: string; emoji: string;
  color: string;                    // акцент категории (заголовок, рамка)
  cells: Record<LevelId, Question[]>;   // в клетке может быть несколько вопросов, в игре берётся случайный
}
interface Question {
  id: string; text: string; answer: string;
  image?: string;                   // 'asset://<file>' (загружено) или 'builtin:<id>' (встроенная иллюстрация)
  valueOverride?: number;           // своя цена, иначе цена уровня
  timerSec?: number;                // свой таймер, иначе из настроек
  catInBag?: boolean; auction?: boolean; noRisk?: boolean; doubleStake?: boolean;
  isPlaceholder?: boolean;          // «Замени меня!» для вопросов про именинницу
  verify?: boolean;                 // факт стоит перепроверить (аналог комментария // verify)
  note?: string;                    // комментарий для редактора
}
```

JSON не поддерживает комментарии, поэтому пометку `// verify` из задания заменяет поле `"verify": true` плюс `"note"` с пояснением.
В dev-режиме такие вопросы помечаются значком 🔍 и собираются фильтром «Проверить факты».

Миграции: `storage.ts` сверяет `schemaVersion` и дополняет недостающие поля значениями по умолчанию, чтобы старые экспортированные `.json` импортировались без ошибок.

## 4. Сторы (Zustand)

1. **`contentStore`** хранит `GameData` и CRUD-операции для категорий, уровней, вопросов, фонов и настроек.
   Любое изменение запускает автосохранение с debounce 500 мс через `window.api.saveGame`, статус сохранения выводится в `SavedBadge`.
2. **`sessionStore`** хранит текущую партию: команды (`id`, имя, аватар, счёт), `activeTeamId`, сыгранные клетки (`categoryId:levelId`), выбранный вариант вопроса в клетке и журнал ответов (`{teamId, categoryId, delta, correct}`), из которого строится статистика.
   Режим предпросмотра получает из редактора снимок `contentStore`.
3. **`uiStore`** хранит текущий экран, открытые модалки, флаг `previewFromDev` и логику авторизации в dev-режиме.

Партия живёт в памяти. Если окно случайно закроют, при следующем запуске её можно будет продолжить: `session.json` пишется в `userData`, на старте предлагается «Продолжить игру?».

## 5. Electron: main / preload / IPC

- `BrowserWindow`: `fullscreen: true`, `minWidth 1280`, `minHeight 720`, `backgroundColor` болотный (без белой вспышки), `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, `webSecurity: true`.
- CSP в `index.html`: `default-src 'self'`, картинки только `self`, `data:`, `blob:`, `asset:`. Любые сетевые запросы блокируются через `session.webRequest`, разрешены только `file:`, `asset:` и `devtools:`.
- Свой протокол `asset://` раздаёт файлы из `userData/assets/`. Путь проверяется, выйти за пределы папки нельзя.
- Каналы IPC (preload отдаёт их как `window.api`):
  - `game:load` → `GameData`: при первом запуске копируется `defaultGame.json`.
  - `game:save(data)`: атомарная запись.
  - `game:reset` → дефолтная игра.
  - `asset:import(bytes, ext)` → `asset://<uuid>.<ext>`. Файл выбирается через `<input type=file>`, в main передаётся `ArrayBuffer`.
  - `asset:delete(name)`.
  - `game:export` / `game:import`: системные диалоги сохранения и открытия. При экспорте картинки встраиваются в JSON как base64, поэтому файл переносим между ПК. При импорте они распаковываются обратно в `assets/`.
  - `category:export` / `category:import`: то же самое для одной категории.
  - `session:save` / `session:load` / `session:clear`.
  - `window:toggleFullscreen`, `app:quit`, `log:write`.
- Сборщик мусора ассетов при сохранении удаляет файлы, на которые больше нигде нет ссылок.

## 6. Режим игры

1. **Старт.** Логотип «СВОЯ ИГРА: ШРЕК» появляется по буквам (stagger и spring). Фон двигается слоями вслед за мышью (параллакс), плавают светлячки. Кнопки «Играть» и «Настройки» (громкость, таймер, полноэкранный режим). Маленький замок в углу открывает dev-режим. Если есть незаконченная партия, появляется «Продолжить».
2. **Команды.** Карточки команд появляются с анимацией, от 2 до 6 штук. У каждой имя и аватар из 12 персонажей (Шрек, Фиона, Осёл, Кот в сапогах, Дракониха, Пиноккио, Пряня, Лорд Фаркуад, Волк, Три слепые мыши, Феи-крёстная, Рапунцель/Гингви…). Команду можно переименовать прямо в карточке и удалить. Предустановленные команды берутся из `defaultTeams`. Кнопка «Начать игру» активна, когда команд не меньше двух.
3. **Поле.** CSS Grid: слева столбец цен, сверху заголовки категорий с эмодзи и цветом, число категорий и уровней любое. Клетки деревянные, с золотыми цифрами, при наведении подсвечиваются. По клику клетка переворачивается и увеличивается (shared layout `layoutId`) в экран вопроса. Сыгранные клетки затемнены, на них печать «сыграно», нажать их нельзя. Справа вверху табло: активная команда пульсирует золотой рамкой, изменение очков отскакивает и показывается как «+300». Кнопка «Завершить игру» спрашивает подтверждение.
4. **Вопрос.** Крупный текст, картинка (если есть) и круговой таймер: тикает на последних 10 секундах, по окончании играет гонг и автоматически показывается ответ. Кнопки:
   - «Показать ответ» (также `Space`);
   - «Верно»: отвечающая команда получает очки и становится активной;
   - «Неверно»: очки снимаются, если вопрос не «без риска». Дальше выбор: передать вопрос другой команде (список ещё не отвечавших) или показать ответ;
   - «Вернуться к полю» (`Esc`): клетка не засчитывается, ход сохраняется.
   После ответа кнопка «К полю» отмечает клетку сыгранной.
5. **Кот в мешке.** Клетка отмечена значком мешка и мерцает. По клику открывается модалка «КОТ В МЕШКЕ!»: мешок трясётся, из него выпрыгивает кот. Активная команда выбирает, кому отдать вопрос (только другим командам). Дальше обычный экран вопроса с плашкой «Отвечает: <команда>» и таймером кота в мешке. При флаге `doubleStake` цена удваивается.
6. **Аукцион.** Модалка со ставками: каждая команда вводит ставку (не меньше цены клетки, не больше своего счёта или цены клетки, если счёт меньше), либо пасует. Кнопка «Ва-банк». Отвечает команда с максимальной ставкой, ставка становится ценой вопроса.
7. **Финал.** Подиум на 1, 2 и 3 места: команды въезжают снизу, над победителем опускается корона. Конфетти и фанфары. Остальные команды выводятся строкой ниже. «Статистика»: по каждой команде число верных и неверных ответов и очки по категориям (таблица и мини-гистограмма). «Сыграть ещё раз» сохраняет команды, обнуляет счёт и поле. «В меню» — выход на старт.

Горячие клавиши (`useHotkeys`): `Esc` — назад или закрыть модалку, `Space` — показать ответ, `Ctrl+Shift+D` — dev-режим, `F11` — полноэкранный режим (обрабатывается в main, работает на любом экране).

## 7. Режим разработчика

Вход по кнопке или `Ctrl+Shift+D`, если задан пароль — через модалку ввода. Слева навигация, справа редактор, вверху бейдж «Сохранено ✓» и кнопки «▶ Предпросмотр», «Экспорт», «Импорт».

1. **Категории.** Список с перетаскиванием (dnd-kit), добавление, удаление с подтверждением, переименование, выбор эмодзи (палитра из ~40 тематических и свободный ввод), выбор цвета (набор палитр и color picker). Экспорт и импорт отдельной категории.
2. **Вопросы.** Сверху сетка «категория × уровень»: в каждой клетке число вопросов и значки флагов (🐱 мешок, 🔨 аукцион, 🛡 без риска, ×2, ⚠ «Замени меня!», 🔍 verify). В клетке список вариантов (добавить, удалить, дублировать). Форма вопроса: цена со степперами ±, текст, ответ, картинка (загрузить, превью, удалить, выбрать встроенную иллюстрацию), четыре чекбокса, таймер. Уровни можно добавлять (например, 600) и удалять с подтверждением, так как удаляются вопросы. Фильтры: «Только плейсхолдеры», «Проверить факты».
3. **Фоны.** Галерея: 4 встроенных фона и загруженные. Отдельный выбор фона для меню, поля, вопроса и финала. Слайдеры размытия и затемнения с живым превью. Загрузка своего фона (jpg, png, webp).
4. **Команды по умолчанию.** Список имён и аватаров, кнопка «Очистить».
5. **Настройки.** Название и подзаголовок игры, общий таймер, таймеры кота в мешке и аукциона, звук и громкость (с кнопкой «проверить звук»), линейка цен (массовое изменение, «×2 ко всем»), штраф за неверный ответ, пароль, «Сбросить всё» (двойное подтверждение).
6. **Предпросмотр.** Запускает игровой режим с текущими данными и двумя тестовыми командами. Плавающая кнопка «← В редактор» возвращает на то же место в редакторе.

## 8. Звук

Бинарные файлы в репозиторий не кладём. Модуль `audio/synth.ts` при старте за ~50 мс рендерит через `OfflineAudioContext` набор звуков в WAV-блобы, и дальше их проигрывает Howler.js. Никакой сети, всё в памяти.
Звуки:
- **click** — деревянный «тук», шум с полосовым фильтром;
- **hover** — очень тихий;
- **open** — «вжух», свип;
- **correct** — мажорное арпеджио на колокольчиках (FM-синтез);
- **wrong** — «бу-у», нисходящий пилообразный тон с фильтром;
- **tick** — последние 10 секунд таймера;
- **timeUp** — гонг;
- **catInBag** — «мяу», свип формант;
- **auction** — молоток;
- **fanfare** — медные аккорды с реверберацией на свёртке, импульс тоже синтезируется.

Громкость и отключение звука берутся из настроек.

## 9. Дизайн

- Токены в `tokens.css`: `--swamp-900 #1f3317`, `--swamp-700 #3a5a2b`, `--swamp-500 #6b8e23`, `--wood-900 #3b2417`, `--wood-600 #6b4226`, `--gold #d4a017`, `--gold-light #f1c94b`, `--cream #f5e6c8`.
- Шрифты: Rubik 800/900 для заголовков и цифр (жирный гротеск с хорошей кириллицей), Montserrat 500/600 для текста.
- Панели «под дерево»: SVG-текстура волокон (`feTurbulence`), фаска через `box-shadow` в несколько слоёв, латунные заклёпки по углам, кованые уголки. Кнопки золотые, с тиснением. Лёгкий шум поверх всего экрана.
- Фоны (SVG, векторные, без кадров из фильмов):
  1. «Болото на закате» — туман, камыши, силуэт домика-пня, светлячки;
  2. «Замок Дракона» — лава, мост, башня;
  3. «Тридевятое королевство» — холмы, город с башнями, закат;
  4. «Таверна „Ядовитое яблоко“» — деревянный интерьер, свечи.
  Каждый фон состоит из 2–3 слоёв для параллакса.
- Аватары: стилизованные SVG-«медальоны» на основе символов персонажей (зелёная голова с ушами-трубочками — Шрек, шляпа с пером — Кот, пряник с пуговицами — Пряня, корона и рыжая коса — Фиона и т.д.).
- Встроенные иллюстрации к вопросам: тот же набор символов плюс предметы (волшебное зеркало, луковица, туфелька, свеча, волшебная палочка), подключаются как `builtin:<id>`.

## 10. Контент по умолчанию (`defaultGame.json`)

7 категорий × 5 уровней (100–500), в каждой клетке 5 вопросов-вариантов, итого ~155–175 вопросов:

1. 🧅 «Шрек 1»
2. 👑 «Шрек 2»
3. 🏰 «Шрек 3 и Навсегда»
4. 🐱 «Кот в сапогах» (спин-оффы)
5. 🍪 «Второстепенные герои»
6. 🎵 «Цитаты и песни»
7. 🎂 «Про именинницу»: 5 плейсхолдеров («Как зовут именинницу?», «Сколько ей лет?», «Любимое блюдо?», «Любимый персонаж Шрека?», «Где мечтает побывать?») с `isPlaceholder: true` и заметной `note`. В редакторе у них значок «Замени меня!», а на стартовом экране dev-режима висит баннер «Осталось заменить N вопросов про именинницу».

Правила контента:
- **100** — разогрев, **200** — простые факты, **300** — нужна внимательность, **400** — детали сюжета, **500** — редкие факты и точные цитаты.
- Только факты, в которых я уверен. Всё менее очевидное (точные формулировки цитат русского дубляжа, имена второстепенных персонажей, детали спин-оффов) помечается `verify: true`.
- 6–7 вопросов с флагом «Кот в мешке» и 3 «Аукциона», распределены по разным категориям и уровням. У части «котов» стоит `doubleStake`.
- `scripts/validate-game.mjs` проверяет: у каждого вопроса есть текст и ответ, id уникальны, нет пустых клеток, число флагов в заданных пределах. Запускается в `npm run check`.

## 11. Сборка и поставка

- `npm run dev` — Vite и Electron с hot reload.
- `npm run check` — `tsc --noEmit`, ESLint и валидация контента.
- `npm run build:win` — `vite build` и `electron-builder --win --x64`. В `dist/` появляются:
  - `Shrek-Jeopardy-<ver>-portable.exe`;
  - `Shrek-Jeopardy-Setup-<ver>.exe` (NSIS, с выбором папки, ярлыками и русским языком установщика).
- Оценка размера ~80–100 МБ на exe (лимит 400 МБ). ОЗУ в игре ~200–400 МБ (лимит 10 ГБ).
- В `electron-builder` включено `asar`, `compression: maximum`, оставлена только русская и английская локали Chromium (`electronLanguages`).
- **Иконка в exe.** На Linux electron-builder вшивает иконку и метаданные через `rcedit`, а это требует Wine. Если Wine поставить не получится, в `afterPack`-хуке ресурсы exe правятся чистым JS (`resedit`). Иконка у exe будет в любом случае.
- **Честно про проверку.** Сборка идёт в Linux-контейнере, настоящей Windows 10/11 у меня нет. Что проверю:
  1. тот же код в Linux-сборке Electron под Xvfb с автотестом Playwright: проход старт → команды → поле → вопрос → кот в мешке → аукцион → финал, dev-режим с правкой, перезапуском и проверкой, что правка сохранилась, скриншоты;
  2. при возможности запуск win-exe под Wine как smoke-тест.
  Финальный запуск на реальной Windows останется за вами, в README будет чек-лист.
- **Доставка exe.** `dist/` в git не коммитится: бинарники раздувают историю, а GitHub отвергает файлы больше 100 МБ. Варианты: собрать у себя (`npm run build:win`, в README), либо, если portable-exe получится меньше 100 МБ, положить его отдельным коммитом в `release/`. Решим, когда увидим размер.

## 13. Риски

| Риск | Что делаю |
